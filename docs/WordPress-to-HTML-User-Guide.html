WordPress → Static HTML

User guide: how the converter works, what it can and cannot do, and the rules to follow
In one sentence: you give the tool a WordPress backup file (.wpress), and it gives you back a ZIP of plain HTML pages that look like the original site and can be uploaded to any web hosting, cPanel included, with no WordPress, PHP or database needed.

1. What you need

ItemDetails
The backupA .wpress file made with the All-in-One WP Migration plugin. Other backup types are not supported.
ComputerWindows PC with the tool installed (run setup.ps1 once). 16 GB RAM is comfortable. The tool measures the machine when each job starts and uses as much of it as is safe, so a faster PC simply finishes sooner.
Free disk spaceAbout 3 × the backup size on the drive where jobs are kept (C:\wpsc-jobs). A 3 GB backup needs about 9–10 GB free.
InternetNot needed for the conversion itself. The tool never contacts your live website.

2. How to start a conversion

Option A: the web screen (easiest)

  • Run run.ps1. A terminal window opens; keep it open.
  • Open http://127.0.0.1:8000 in your browser.
  • Under File on this computer, pick your backup. Nothing is uploaded or copied; it is read where it is.
  • Check the options. One folder per page and Link to folders are on by default (see section 4), and Concurrent pages is set to Auto. Then click Start conversion.
  • The screen shows the current step, the time left for that step and for the whole job, and a live log.

Option B: the command line

cd B:\Automation\wordpress-to-html
.venv\Scripts\python.exe convert.py "C:\bkp\site.wpress" --jobs-dir C:\wpsc-jobs -o C:\wpsc-jobs\exports --screenshots

How many pages render at once is measured from your PC; add -c 5 to force a number. --screenshots turns on the visual comparison. --flat gives about.html-style pages instead of folders, and --file-links writes links as contact-us/index.html (see below).

3. The workflow, step by step

Every job goes through the same 9 steps. Times are from a real 3.2 GB site with 686 pages.

1

Extract the backup

Unpacks the .wpress file: the WordPress files, themes, plugins, images and the database export.

About 5 minutes
2

Restore WordPress

Builds a private, temporary copy of the website on your computer: its own small database and web server, invisible to anyone else. All links that point to the live domain are switched to this local copy, so nothing is ever fetched from the real website. The theme and plugins are switched on, and cache or security plugins that would get in the way are paused, in the copy only.

About 20 minutes (mostly loading the database)
3

Start WordPress

Starts the local copy and waits for the first page. The very first page view after a restore can take several minutes, because WordPress and Elementor rebuild their caches. The tool waits up to 15 minutes for that.

1–5 minutes
4

Find all pages

Asks WordPress for every published page, post, category and custom content type, reads the sitemaps, and later also follows links found inside pages, so pages that nothing else lists are caught too.

Under 1 minute
5

Render pages

Opens every page in a real browser (Chrome), lets everything load and animate, scrolls down so lazy images appear, then saves the finished page exactly as a visitor would see it. Analytics and tracking are blocked, so your statistics are not affected. Images, CSS and scripts are read straight from disk for speed.

The longest step: about 25 minutes for 686 pages
6

Create the HTML files

Rewrites every saved page for static hosting. Every menu, footer, sidebar and button link is changed to point at the exported page (for example contact-us/; see "Link style" below). A page that cannot be written is recorded as failed; the job continues with the rest.

About 7 minutes
7

Collect assets

Gathers every image, stylesheet, script and font the pages use, from the backup's own files. It also includes the "on-demand" scripts (for example a carousel's code) that only load while a page runs.

Under 1 minute
8

Check and repair

Tests the finished site. Any file that is missing from the export but exists in the backup is copied in automatically and checked again. It also opens one or two pages of every page design in a browser to look for errors, and compares screenshots of the original and the export.

About 10 minutes
9

Package the ZIP

Puts the whole site into one ZIP file and writes a report explaining what was found.

About 3 minutes
Typical total: about 1–1½ hours for a 3 GB backup with around 700 pages. Smaller sites finish much faster; sites with thousands of pages take longer.

4. What you get

OutputWhere / what
The ZIP (to upload)C:\wpsc-jobs\exports\<site-name>-static.zip. An existing ZIP is never overwritten; a new one gets -2, -3 added to its name.
The unzipped siteC:\wpsc-jobs\<job-id>\output\. Open index.html to browse it from your computer.
The reportC:\wpsc-jobs\<job-id>\report\conversion-report.html. Read the Quality check and Static HTML limitations sections.
Screenshot comparisonsC:\wpsc-jobs\<job-id>\screenshots\: original, export and a "diff" image with the differences in pink.

Page layout

SettingResult
One folder per page (default)contact-us/index.html. On a web server the address stays /contact-us/, exactly like WordPress, so Google rankings and old links keep working.
One file per page (--flat)contact-us.html. The web addresses change to /contact-us.html.

Link style

SettingResult
Link to folders (default)Links are written as contact-us/, the same addresses WordPress used. This is what you want for cPanel or any web server. Opened straight from a disk, such a link shows the folder's file list instead of the page, because there is no server to open index.html for you.
Link to files (untick the box, or --file-links)Links are written as contact-us/index.html. Works on a web server and when opening the pages from a disk or USB stick. The addresses are longer.

Putting it online (cPanel)

  • Open cPanel, then File Manager, then public_html.
  • Upload the ZIP and click Extract, so that index.html ends up directly inside public_html.
  • Open your domain to check. The site also works inside a sub-folder.

6. What the tool cannot do (limitations)

A static site has no server program behind it. Anything that must send information to the website, or ask it for new information, will look right but will not work.

FeatureIn the exportWhy / what to do
Contact and quote forms (Elementor Forms, Contact Form 7, WPForms)Look right, cannot send Sending needs WordPress. Connect the form to a form service (Formspree, Web3Forms, Getform) or a small PHP mail script. cPanel supports PHP, so a mail script works there.
reCAPTCHAShows, cannot verifyChecking needs a server; handled by the form service or mail script.
Site searchDoes not workUse a static search tool or Google site search.
"Load more", AJAX filters, infinite scrollFirst results onlyExtra results are fetched from WordPress at click time.
Popups whose content is fetched when openedMay be emptyRare with Elementor. The report lists pages that use AJAX.
Posting comments, user login, member areasDo not workNeed PHP and the database. Existing comments are shown.
WooCommerce cart, checkout, payments, stockDo not workProduct pages can be shown as a catalogue only.
Anything that changes on its own (live prices, scheduled posts, counters)FrozenThe export is a snapshot of the day it was made. Re-convert to update.
Pages behind a login, drafts, private pagesNot exportedOnly published, public pages are converted.
Pages nothing links to and WordPress does not listMay be missedVery rare. Up to 5,000 pages per job by default.
Fonts and scripts from other websites (e.g. Google Fonts)Still load onlineKept pointing at their original service by default.
Images missing from the backup itselfStay missingThey are broken on the live site too. The report lists them; fix them in WordPress.
Every report lists these for your specific site under "Static HTML limitations", for example "Elementor Forms on 1 page". Read it before publishing so you know which forms or features need attention.

7. Understanding the Quality check

ResultMeaning
Repaired automaticallyFiles that were missing from the export but found in the backup, and copied in. Nothing for you to do.
ProblemsSomething the conversion got wrong. The job is shown as "Completed with N problem(s)". The ZIP is still made; check the listed pages before publishing.
Source issuesThings that are broken on the original website too: links to pages that do not exist, images missing from the backup. Fix them in WordPress, then re-convert.
Visual similarityHow closely the export's screenshots match the original, compared per page design. Around 90% or more is normal. Carousels stopping on a different slide lower the score without being a real problem; look at the pink "diff" image to judge.

8. Rules to follow

  1. Use only .wpress backups made with All-in-One WP Migration.
  2. Keep 3 × the backup size free on the jobs drive before starting.
  3. Let the tool decide how hard to work. "Auto" measures cores and memory when each job starts. Set a number by hand only if you want to keep the PC free for other work.
  4. One conversion at a time on a normal PC. Each job runs its own database, web server and browser; a machine with 8 or more cores and 32 GB of memory may run two.
  5. If a job stops or fails, resume it; do not start again. Resume re-uses everything already done: the restored site, the database and every page already rendered. In the web screen click Resume; on the command line use --resume <job-id>.
  6. Never resume the same job from the web screen and the command line at the same time.
  7. Do not delete a job folder (C:\wpsc-jobs\<job-id>) until you are happy with the result. It is what makes resume possible.
  8. The tool never deletes your data by itself. Your backup file is only read. A previous output is renamed to output-previous-…, and an existing ZIP is never overwritten.
  9. Keep the terminal window open while a job runs. Closing it stops the job (it can be resumed). Clicking inside the window is safe.
  10. Read the report before publishing, especially "Quality check" and "Static HTML limitations".
  11. Fix content problems in WordPress, not in the export. Then make a new backup and convert again, so the next export is correct too.
  12. The export is a snapshot. After changing the WordPress site, make a new backup and re-convert.
  13. Keep the web screen private. It only runs on your own computer (127.0.0.1); do not expose it to the network.

9. Quick troubleshooting

What you seeWhat to do
Job failed while starting WordPress or renderingResume it. Nothing already done is repeated.
"Not enough free space"Free up space on the jobs drive (3 × the backup size), then start or resume.
Job list in the web screen looks emptyPress Ctrl+F5 to reload the page.
"Completed with problems"Open the report, then the Quality check section. The ZIP is usable; review the listed pages.
A form does not send on the live static siteExpected. Connect it to a form service or a PHP mail script (section 6).
Clicking a link opens a folder list instead of a pageYou are opening the site from a disk, where folder links cannot work. On a web server it is correct. To browse locally, untick Link to folders and convert again.
Background images missing on the local previewNormal when the live site is offline; the final export includes them. Check output\index.html.
